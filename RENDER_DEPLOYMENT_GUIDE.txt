OVERVIEW
--------
This guide walks you through deploying your Gemstone Price Prediction FastAPI
application to Render using Docker. Your project already has a working Dockerfile,
so the process is straightforward.

Render is a cloud platform that lets you deploy web services for FREE (with limits)
using Docker or native runtimes, without needing a credit card for basic usage.

--------------------------------------------------------------------------------
PREREQUISITES (Things You Need Before Starting)
--------------------------------------------------------------------------------

1. A GitHub account (https://github.com)
   - Your project code must be pushed to a GitHub repository (public or private).

2. A Render account (https://render.com)

   - You can sign up using your GitHub account (recommended — easier to connect).

3. Your project must be pushed to GitHub with all the required files:
   - app.py

   - templates/ folder (with index.html)

IMPORTANT: The "artifacts/" folder contains your trained model (.pkl files).
Make sure it is NOT in .gitignore so it gets pushed to GitHub!

STEP 4: CREATE A NEW WEB SERVICE ON RENDER
--------------------------------------------------------------------------------

  Step 4a: Start a New Service
  -----------------------------
  1. On your Render Dashboard, click the "New +" button (top right area)
  2. From the dropdown menu, select "Web Service"

  Step 4b: Connect Your GitHub Repository
  ----------------------------------------
  1. Click "Connect account" next to GitHub (if not already connected)
  2. In the search box, type: gemstone-price-prediction
  3. Find your repository and click "Connect"

  Step 4c: Configure the Service Settings
  -----------------------------------------
  Fill in these settings on the configuration page:

  Name:
    gemstone-price-prediction
    (or any name you like — this will be part of your URL)

  Region:
    Oregon (US West) — recommended, or choose what's closest to you

  Branch:
    main

  Runtime:
    Docker
    (VERY IMPORTANT — select "Docker" because your project has a Dockerfile)

  Instance Type:
    Free
    (The free tier is enough to test your app. Note: Free tier spins down
     after 15 minutes of inactivity — first request after that will be slow.)

  Leave all other settings as their defaults for now.

  Step 4d: Click "Create Web Service"
  -------------------------------------
  Click the "Create Web Service" button at the bottom of the page.
  Render will now start building and deploying your application!

--------------------------------------------------------------------------------
STEP 5: WAIT FOR THE BUILD TO COMPLETE
--------------------------------------------------------------------------------

After clicking "Create Web Service", Render will:

  1. Clone your GitHub repository
  2. Build your Docker image (runs pip install, etc.)
  3. Start the FastAPI server

This process typically takes 5-15 minutes the first time because it needs to
install catboost, scikit-learn, xgboost, and other heavy packages.

You can watch the live build logs in the "Logs" tab on your Render service page.

What a successful build looks like in the logs:
  ...
  Successfully built <image-id>
  Successfully tagged <image-name>
  ==> Starting service with 'uvicorn app:app --host 0.0.0.0 --port 8000'
  INFO:     Started server process
  INFO:     Waiting for application startup.
  INFO:     Application startup complete.
  INFO:     Uvicorn running on http://0.0.0.0:8000

When you see "Your service is live", the deployment is complete!

STEP 7: RE-DEPLOYING AFTER CODE CHANGES
--------------------------------------------------------------------------------

Whenever you update your code and push to GitHub, Render can automatically
redeploy your app.

  Option A: Auto-Deploy (Recommended)
  -------------------------------------
  By default, Render enables "Auto-Deploy". This means every time you push
  new code to your "main" branch on GitHub, Render automatically rebuilds
  and redeploys your app. No manual action needed.

  How to push updates:
    git add .
    git commit -m "Your update message"
    git push origin main

  Render detects the push and starts a new deployment automatically.

  Option B: Manual Deploy
  ------------------------
  In your Render dashboard, go to your service and click "Manual Deploy"
  → "Deploy latest commit"

STEP 8: TROUBLESHOOTING COMMON ISSUES
--------------------------------------------------------------------------------

ISSUE 1: Build fails with "No module named 'src'"
  CAUSE  : The setup.py package install may have failed.
  FIX    : Check the build logs. Make sure your Dockerfile has this line:
             RUN pip install -e . --no-deps
           Your current Dockerfile already has this, so it should be fine.

ISSUE 2: Build fails with "FileNotFoundError: model.pkl"
  CAUSE  : The artifacts/ folder was not pushed to GitHub (it was in .gitignore).
  FIX    : Open .gitignore, remove or comment the "artifacts/" line, then run:
             git add artifacts/
             git commit -m "Add model artifacts"
             git push origin main

ISSUE 3: Build is very slow (15+ minutes)
  CAUSE  : Installing catboost takes a long time on the first build.
  FIX    : Just wait. Subsequent builds may be faster if Render caches layers.

ISSUE 4: App loads but prediction returns an error
  CAUSE  : The model file path may be different inside Docker.
  FIX    : Make sure your predict pipeline uses paths relative to the project
           root (e.g., "artifacts/model.pkl" not absolute paths).

ISSUE 5: "Service unavailable" or slow first load on Free tier
  CAUSE  : Free tier Render services "spin down" after 15 min of inactivity.
           The first request after spin-down takes 30-60 seconds.
  FIX    : This is normal on the free tier. Upgrade to a paid plan ($7/month)
           if you need the app always running instantly.

ISSUE 6: Port-related error during deployment
  CAUSE  : Render expects the app to listen on the port specified in the
           Docker CMD command.
  FIX    : Your Dockerfile already uses port 8000 and --host 0.0.0.0,
           which is correct. No changes needed.

STEP 9: ENVIRONMENT VARIABLES (Optional)
--------------------------------------------------------------------------------

If your app needs any secret keys or environment variables, do NOT put them
in your code. Use Render's Environment Variables feature instead.

  How to add Environment Variables:
  1. Go to your Render service dashboard
  2. Click "Environment" on the left sidebar
  3. Click "Add Environment Variable"
  4. Enter the Key and Value
  5. Click "Save Changes"
  6. Render will automatically redeploy with the new variables

In your Python code, access them with:
  import os
  my_value = os.getenv("MY_VARIABLE_NAME")

For a personal project or portfolio, the free tier is more than enough.
